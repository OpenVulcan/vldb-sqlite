# SQLite 文件锁修复与原生发行

## 任务目标

修复正式版本在文件锁竞争时忽略未获取锁结果的问题，发布兼容的 `v0.1.7` 原生依赖，供 VMM 更新固定下载版本与摘要。已公开的旧版本保持不变。

## 执行步骤

1. 在原代码上增加真实文件锁竞争回归并确认失败。
2. 显式处理未获取锁的结果，在任何锁内容写入之前返回占用错误。
3. 验证竞争者不能释放原持有者的锁，原持有者释放后可以重新获取。
4. 在五个原生平台构建发行程序和动态库，并执行库测试。
5. 下载草稿的全部压缩包与摘要，核对资产集合、字节摘要、库布局及 Windows 实际动态库行为。
6. 所有验收通过后公开新版本，随后更新 VMM 的固定依赖与摘要，重新执行完整发行验证。

## 技术选型

沿用当前 Rust 工具链、`fs4 0.13.1`、SQLite ABI 和文件锁路径。修复返回值处理，不引入新核心库，不变更数据库格式或锁协议。GitHub 原生发行与 crates.io 发布分别记录。

## 验收标准

- 原代码回归测试确实失败，修复后真实锁竞争返回 `WouldBlock`。
- 五个平台的库测试全部通过，发行包含十个压缩包和十份摘要文件。
- 下载资产字节与 GitHub 摘要及随包摘要一致，Windows 动态库能通过 VMM 的真实文件锁测试。
- 完成连续五轮复审，不以跳过测试、修改旧发行资产或放松断言代替修复。
- 未验证完成时保留草稿，不公开不完整版本。

## 当前执行记录

原代码在 Windows 上新增的锁竞争测试失败，错误类型为 `Uncategorized`，证明其错误来自竞争之后的文件操作；修复后全部二十四项库测试通过。跨平台原生发行与下载验收待执行。
